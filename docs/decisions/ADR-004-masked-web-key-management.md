# ADR-004 · 网页 Key 管理采用掩码快照与启动自动加载

- 状态：accepted（D1–D4 于 2026-08-28 获用户确认）
- 日期：2026-08-28
- 关联：S06-web-key-management；[设计稿](../superpowers/specs/2026-08-28-s06-web-key-management-design.md)

## 背景

`/api/secrets` 此前把 `~/.secrets.env` 的明文值返回给已认证浏览器，前端还提供明文回显；服务重启后该文件不会自动加载，README 曾因此出现过度承诺（已修正）。用户决定将该能力纳入 v0.1，前提是先完成安全加固。

## 决定

1. **浏览器永不接收明文值**：GET/POST 响应中的值统一为固定掩码 `••••••••`；页面编辑采用「留空 = 保持不变」的覆盖式写入，不做旧值回显。键名保持可见（用户需要靠键名识别条目）。
2. **服务启动时自动加载 `~/.secrets.env`**：缺失的环境变量被填充；启动命令已显式设置的同名变量不被覆盖。写入文档事实后，重启行为成为产品承诺而非外部环境巧合。
3. **边界固定**：该面板只服务群聊成员/自定义 CLI 的本机 Key；DeepSeek 护航 Key 仍只走 S01 macOS Keychain。两条凭据路径不互相替代、不互相混用证据。

## 理由

- 明文回显使浏览器内存、DevTools、可能的代理日志都成为 Key 泄露面；掩码 + 覆盖式编辑以极小的体验代价（不能回看旧值）消除该暴露面。
- 自动加载消除「保存后生效、重启后失效」的不一致，也消除用户对启动方式的隐式依赖。
- 固定边界防止该高风险路径被误用于需要 S01 级别保护的凭据。

## 后果

- 用户无法在面板里查看已存 Key 的明文（需直接查看本机 `~/.secrets.env` 文件）；这是接受的取舍。
- 服务端加载逻辑成为攻击面的一部分：解析器只处理 `export KEY='value'` 形态，保持简单与可测试。
- 若未来需要「查看明文」，必须作为新的高风险决策重新评估，不得在本边界内隐式扩展。
