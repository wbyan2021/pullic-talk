- 范围：S04 项目与证据 UI 的临时需求
- 相关事实源：[NOW.md](../../NOW.md)、[PRODUCT.md](../../PRODUCT.md)、[CODEMAP.md](../../CODEMAP.md)

## 背景与问题

当前 `public/index.html` 将 `#project-wrap` 与 `#execution-panel` 作为两个并列区域。`public/js/execution.js` 虽然读取活动项目，但 Pi 输入面板始终渲染在项目列表之外，用户需要在项目卡和运行面板之间来回确认目标项目，容易把任务输入到错误的项目上下文。

另外，Pi 启动前会执行 `pi auth check --provider <P> --json`。`P` 的优先级是显式配置、`PI_AUTH_PROVIDER`、`PI_PROVIDER`、默认 `google`。本机已有 `aliyun-token-plan` 就绪而默认 `google` 未就绪，因此真实验收必须显式设置 provider；这属于运行配置问题，不属于 UI 面板移动逻辑。

## 已确认的交互规则

1. 只有当前 `ACTIVE` 项目显示 Pi 任务输入与运行面板。
2. 用户点击另一个项目的“设为活动”后，面板从旧项目卡片下方移动到新项目卡片下方。
3. 非活动项目不显示任务输入框、运行状态和验收操作，避免产生多个任务目标。
4. 活动项目卡仍展示项目边界、AI 交接状态和原有项目操作；Pi 面板作为该卡片的下属区域出现。
5. 面板移动只改变展示位置，不改变服务端的活动项目状态、Pi 执行契约、证据记录或认证流程。
6. 页面刷新后由服务端 `activeProjectId` 重新决定面板归属；浏览器不保存项目或任务状态。

## 方案与取舍

### 方案 A（采用）：项目卡片内嵌单一共享面板

由项目列表负责渲染项目卡片；当卡片项目 id 等于 `activeProjectId` 时，在卡片内容末尾挂载一个共享的 `#execution-panel` 容器。活动项目变化时，DOM 容器移动到新卡片，`execution.js` 继续使用现有 API 和状态模型。

- 优点：改动小，保持单一执行状态和单一 Pi 实例；输入位置与活动边界天然一致。
- 缺点：项目卡片的高度会增加；活动切换时面板会随卡片重排。

### 方案 B：每个项目卡片各自创建独立面板

每张卡都渲染一套面板，但只有活动项目启用控件。

- 优点：布局实现直观。
- 缺点：容易产生重复状态、重复轮询和过期输入；不符合单任务 WIP=1，不采用。

### 方案 C：点击项目后打开浮层或抽屉

面板浮在项目卡旁边或下方。

- 优点：不改变卡片高度。
- 缺点：仍需要用户记忆当前目标，移动端/窄窗口定位更复杂，不采用。

## 组件与数据流

- `public/index.html`：将执行面板容器放入项目视图的可移动挂载区域，保持单一 DOM 节点。
- `public/js/project.js`：根据 `/api/project/status` 的 `activeProjectId` 渲染活动卡，并提供面板挂载点；切换活动项目后触发同一事实源刷新。
- `public/js/execution.js`：保留现有 `/api/project/execution/*` 与 `/api/evidence/*` 调用，仅在初始化、活动项目变化或项目列表重绘后把自身容器挂载到活动卡的挂载点。
- `public/css/project.css`、`public/css/execution.css`：补充卡片内嵌间距、边界和窄屏布局，不改变风险颜色或状态语义。
- 服务端不改动：活动项目仍由 `ProjectBoundary` 决定，`PiExecutor` 仍只读取服务端活动项目并执行 auth check。

## 状态与错误处理

- 没有活动项目：项目卡片不挂载 Pi 面板；现有“请先设为活动”的提示保留在项目视图中。
- 活动项目失效：不挂载可启动面板，显示项目失效提示；不能绕过项目边界执行。
- 活动项目切换时任务正在运行：不自动停止、不迁移正在运行的任务；面板继续显示当前任务，切换活动项目应被后端 busy/边界状态保护，并提示用户先处理运行中的任务。
- Pi auth 未就绪：面板显示稳定错误 `pi_not_authenticated`，引导使用正确的 `PI_AUTH_PROVIDER` 启动服务；不显示原始 stderr 或任何凭据。

## 验收标准

- [ ] 初始没有活动项目时，不出现 Pi 输入面板。
- [ ] 设为活动后，Pi 输入框紧接出现在该项目卡片下方。
- [ ] 切换活动项目后，旧项目不再显示输入框，新项目显示同一执行面板。
- [ ] 输入任务时刷新/轮询不会清空输入；面板移动不会复制或丢失文本。
- [ ] Pi 任务、停止、时间线、Git 证据、验收命令和交接记录行为与现有 S04 契约一致。
- [ ] 活动项目失效或无活动项目时不能启动 Pi。
- [ ] UI 单元测试覆盖挂载位置、切换归属、无重复面板和现有安全 DOM/API 约束。
- [ ] `npm test`、语法检查、差异检查和严格状态校验通过。

## 非目标

- 不支持多个项目同时运行 Pi。
- 不改变 Pi provider、认证凭据、任务 API、证据模型或黑匣子格式。
- 不添加浏览器持久化，不把任务文本或 Key 写入普通配置文件。
- 不在本需求中修复或替换 Pi CLI 的认证机制；认证 provider 通过启动环境显式配置。
