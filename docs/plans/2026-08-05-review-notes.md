## 1. 一句话看懂这次变更

产品从「**AI·OPS DECK = 工具控制中心**」升级为「**AI·OPS COCKPIT = 有 AI 护航的本地 Agent 运维驾驶舱**」。
本轮详细设计仍以 **通电 → 校准 → 待命** 为主；复议后已经补上从待命到任务交付的产品级轮廓，点火、地面测试、第一次试飞和任务卡交互仍待后续设计（旧版试飞流程见 [历史备份](../diagrams/archive/2026-08-05-first-start-and-first-flight-flow-v1.md)）。

## 3. 流程要点（草案 §3–5）

- **通电**：环境检查 → DeepSeek Key（外跳申请、返回续接）→ Keychain 安全保存 → 护航 AI 上线 → 装 Pi → 智能同步 → 通电完成
- **校准**：认识 8 个模块；完成安全待命所需的最低必要校准，高级能力渐进配置 → 综合自检 → 校准报告 → 待命
- **待命最低条件**：护航 AI 在线 + 1 个能源 + 1 个 Agent 健康 + 项目边界 / 暂停 / 恢复点 / 黑匣子可用

## 4. 评审意见

### 4.1 🔴 必须先解决

1. **价值缺口**：流程终点是「待命」，用户还没看到 AI 干成任何事。
   → 压缩校准为「快速通电 + 渐进校准」（6 个模块默认配置，用到时再引导）；
   → **首飞任务延后实现但不延后定义**（建议：只读扫描项目、生成体检报告，零写风险、有交付）。
2. **用户画像矛盾**：「完全不懂 CLI 的小白」站不住（他们用网页版 ChatGPT），且申请 Key 是带付费步骤的外部漏斗。
   → 画像改为「**半专业用户**」：会装 App、会复制 Key，但不想碰配置文件和终端。
3. **缺统一状态模型**：产品全面「状态驱动」，但未定义实体 × 状态机 × 事件词汇表。
   → 补一章：驾驶舱、能源、Agent、项目、任务、安全区的状态枚举、迁移条件、触发事件；UI、护航 AI、黑匣子、失败处理表共用同一套模型。这是「护航 AI 始终理解当前状态」能否成立的前提。

### 4.2 🟡 建议修改

4. **决定队列太薄**（夜航的生死线、差异化主战场）：
   → 补决定卡片结构（上下文 / AI 想做什么 / 为什么 / 替代方案 / 不处理的后果 / 一键批准·拒绝·替代）；
   → 补**常设指令**（预设规则，如「项目内修改不用问」「git push 永远问」）；
   → **信任阶梯**做成一等公民机制：L1 每步都问 → L2 保守自主 + 检查点 → L3 夜航只问关键抉择。
5. **v1 机组过度设计**：当前 CLI Agent 能力高度重叠，多机组放大失败模式（合并、冲突、成本翻倍）。
   → 首飞用**单 Agent 执行 + 护航 AI 监督**；机组组建作为第二形态。
6. **隐喻纪律**：状态与情绪用隐喻（通电 / 待命 / 夜航很好），功能标签保持直白（不建词典）；补两个机会点：
   → **起飞前检查单**：安全区、恢复点、预算上限逐项点绿，把安全变成可感知的安心感；
   → **油量表**：预算余量 + 实时燃烧率做成主仪表，费用焦虑是新手前三劝退项。

### 4.3 🟢 界面小项

7. 右侧栏只回答一个问题「**现在该干什么**」：一次一张主卡片，其余折叠进队列，防杂物间化。
8. 待命页不能空：中央主仪表主动提议第一个任务（呼应 4.1-1 的首飞定义）。

### 4.4 ✅ 保留，不改

- 保守自主原则（§6.6）
- 可回溯安全区替代重复审批弹窗（§6.6）
- §10 失败模式表 —— 建议直接转成**错误设计规范**：每个错误 = 解释 + 原因 + 一个建议动作
- §12 未决项清单与开发隔离的纪律

### 4.5 复议结论

| 处理 | 意见 | 最终处理 |
|---|---|---|
| 直接吸纳 | 统一状态模型 | 在总览补充状态实体与结构化事件基础，精确状态机留到任务设计 |
| 直接吸纳 | 首版单 Agent + 护航 AI | 作为第一条正式任务闭环原则，多 Agent 保留为后续增强 |
| 直接吸纳 | 隐喻纪律、右侧单一下一步、错误规范 | 纳入界面与错误设计原则 |
| 改写吸纳 | 快速通电 + 渐进校准 | 关键安全能力必须先校准，额外 Agent 与 Harness 渐进配置 |
| 改写吸纳 | 用户画像 | 初期面向会安装 App、复制 Key 的用户；长期仍降低到普通用户门槛 |
| 改写吸纳 | 决定卡、常设指令、信任阶梯 | 保留决定卡与按动作类型的常设规则；不采用“每一步都问”的 L1 模式 |
| 改写吸纳 | 首飞项目体检 | 作为首个验证候选，不固定为所有用户唯一的第一次任务 |
| 改写吸纳 | 油量表 | 首版显示预算与明确标注的本地估算，不追求虚假实时精度 |
| 不吸纳 | 六个模块全部默认跳过、用到再配 | 项目边界、暂停停止、恢复点和黑匣子属于进入安全待命的最低条件 |
| 不吸纳 | 立即回写事实源并开工 | 先确认产品总纲，再更新 PRODUCT、NOW 和开发切片 |

## 6. 补充技术风险备注（不属于产品决策）

- 护航 AI 需要结构化输出与工具调用，DeepSeek function calling 可用但需适配层设计。
- DeepSeek 无按次用量查询 API，仪表中的「费用状态」只能靠本地 token 估算，需在设计中写明。
- 总览已经补充从现有代码到目标驾驶舱的迁移轮廓；具体切片序列仍需等版本唯一目标确认后制定。
